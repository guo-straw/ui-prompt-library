## 结构

- `SKILL.md` — Agent 技能文件：选用规则与维护流程（根目录，先读它）
- `prompts.json` — 全库机器可读数据（空间和 Skill 的数据源）：id、标题、分类、风格标签、场景、英文提示词（复制用）、中文说明、适用工具、预览与验证字段；相似效果条目带 `group` / `variant_label`，空间里归纳为一张卡片、风格可切换
- `prompts/<分类>.md` — 按分类的人读版，已验证条目内嵌展示 GIF
- `favorites.json` — 收藏清单（id 数组）。**选设计时收藏优先**
- `inbox.md` — 收集待整理区：新收集先落这里（标来源和日期），整理去重后才进正式库
- `previews/<id>.png` — 已验证条目的生成效果图（静态效果直接展示图片）；`previews/<id>.gif` — 仅动效类条目有，真实呈现入场/交互等动效

## 怎么用

1. 做 UI 设计时，先按场景/分类找候选，再按风格标签匹配；收藏的排最前，已验证的优先于未验证的。细则见 `SKILL.md`。
2. 每条的英文提示词可直接复制到 v0 / Lovable / Cursor 等工具生成界面；中文说明帮你快速判断长什么样。
3. 带 ✅ verified 标记的条目是已按提示词实际生成并目检通过的，效果以 `previews/` 里的效果图为准；动效类条目另有 GIF 展示真实动效。

## 维护规则

1. 新增提示词必须有：唯一 id（英文短横线）、分类、至少 1 个风格标签、场景、英文提示词、中文说明、适用工具。
2. 入库前查 `prompts.json` 去重：同一场景+同一风格只保留一条；相似效果不同风格的归纳成一个风格组（`group`/`variant_label`），空间里一张卡片切换风格、展示同步切换。
3. **先验证、后入库**：收集的提示词先放 `inbox.md` 待验证区；有来源视频的核对视频内容与提示词一致并从视频截取展示素材（动效类截 GIF、静态截关键帧），无来源视频的实际生成一次并目检；通过后才进 `prompts.json` 并标 `verified`，效果图存 `previews/`（动效类另存真实动效 GIF）；视频取不到的不入库、不许用生成图冒充。不通过就改提示词重验或留待验证区并记录差距，绝不先入库再补验。
4. 收藏只增删 `favorites.json`，不动提示词正文。
5. 每次改库都 git commit（信息写清动作和条目），并同步更新本 README 的状态与统计。
